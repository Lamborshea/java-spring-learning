L20 缓存

⏱ 1.5 小时 📦 进阶功能 🎯 @Cacheable + Redis
为什么要缓存？

数据库查询慢（10ms - 100ms），同一个查询 1000 次，第一次查 DB，后面查缓存。

读多写少的场景：用户主页、商品详情、文章内容。

本节目标

  • 理解缓存策略
  • 会用 @Cacheable、@CacheEvict
  • 会用 Redis 做分布式缓存

1. Spring Cache 三大注解

注解作用类比
@Cacheable查询时缓存memoize
@CachePut更新时刷新缓存cache.set
@CacheEvict删除缓存cache.delete

3. @Cacheable 用法

@Service
public class UserService {

  @Cacheable(value = "user", key = "#id")
  public User findById(Long id) {
    // 第一次调用执行，后续命中缓存
    log.info("从数据库查 user {}", id);
    return userRepository.findById(id).orElse(null);
  }

  @Cacheable(value = "user", key = "#username", unless = "#result == null")
  public User findByUsername(String username) {
    return userRepository.findByUsername(username);
  }
}
key 的写法
  • #id - 参数 id
  • #username - 参数 username
  • #user.id - 参数对象的字段
  • #root.methodName - 方法名
  • #root.target - 目标对象

4. @CacheEvict 删除缓存

@Service
public class UserService {

  @CacheEvict(value = "user", key = "#id")
  public void deleteById(Long id) {
    userRepository.deleteById(id);
  }

  // 清空整个 user 缓存
  @CacheEvict(value = "user", allEntries = true)
  public void deleteAll() {
    userRepository.deleteAll();
  }

  // 更新后清缓存
  @CachePut(value = "user", key = "#user.id")
  public User update(User user) {
    return userRepository.save(user);
  }
}

5. 缓存策略

请求 → 查缓存（命中返回）
        ↓ 未命中
       查 DB
        ↓
      写入缓存
        ↓
      返回结果

6. 缓存问题

问题说明解决
缓存穿透查不存在的 key，每次都打 DB空值也缓存
缓存击穿热点 key 过期，瞬间大量请求分布式锁、不过期
缓存雪崩大量 key 同时过期过期时间加随机

7. 实战代码

@Service
@RequiredArgsConstructor
public class ArticleService {
  private final ArticleRepository articleRepository;

  @Cacheable(value = "article", key = "#id", unless = "#result == null")
  public Article getById(Long id) {
    log.info("DB query: article {}", id);
    return articleRepository.findById(id).orElse(null);
  }

  @CachePut(value = "article", key = "#article.id")
  public Article update(Article article) {
    return articleRepository.save(article);
  }

  @CacheEvict(value = "article", key = "#id")
  public void delete(Long id) {
    articleRepository.deleteById(id);
  }
}
