L11 RESTful API 设计

⏱ 1.5 小时 📦 Web 开发 🎯 API 设计规范
REST 是什么？
REST = Representational State Transfer，是一套"用 URL 表达资源、用 HTTP 方法表达操作"的设计风格。

本节目标

  • 理解 REST 架构风格
  • 掌握资源命名规范
  • 正确使用 HTTP 方法
  • 返回合适的 HTTP 状态码

1. 资源命名

URL 应该只表达资源，不表达操作。

场景错误 ❌正确 ✅
用户列表/getUsersGET /users
用户详情/getUserById/123GET /users/123
创建用户/createUserPOST /users
更新用户/updateUser/123PUT /users/123
删除用户/deleteUser/123DELETE /users/123
用户文章/getUserArticles/123GET /users/123/articles
命名规范
  • 用复数名词，不用动词
  • 用 小写 + 中划线（如 /user-articles）
  • 嵌套资源表达从属关系

2. HTTP 方法语义

方法用途幂等？安全？
GET查询是是
POST创建否否
PUT完整更新是否
PATCH部分更新否否
DELETE删除是否

幂等 = 多次执行结果相同。POST /users 调 5 次会创建 5 个用户，DELETE /users/123 调 5 次结果都是"已删除"。

3. 状态码速查

状态码含义何时用
200 OK成功GET 成功、PUT 成功
201 Created创建成功POST 成功创建
204 No Content无内容DELETE 成功（无返回体）
400 Bad Request请求参数错参数校验失败
401 Unauthorized未认证没登录/token 无效
403 Forbidden无权限登录了但角色不够
404 Not Found资源不存在查询的 id 不存在
409 Conflict冲突唯一键冲突
500 Server Error服务器错误未捕获的异常

4. 完整 Controller 示例

@RestController
@RequestMapping("/api/users")
public class UserController {

  @GetMapping           // GET /api/users
  public List<User> list() { ... }

  @GetMapping("/{id}")  // GET /api/users/123
  public User get(@PathVariable Long id) { ... }

  @PostMapping          // POST /api/users
  @ResponseStatus(HttpStatus.CREATED)  // 201
  public User create(@RequestBody CreateUserRequest req) { ... }

  @PutMapping("/{id}")  // PUT /api/users/123
  public User update(@PathVariable Long id, @RequestBody UpdateUserRequest req) { ... }

  @DeleteMapping("/{id}")  // DELETE /api/users/123
  @ResponseStatus(HttpStatus.NO_CONTENT)  // 204
  public void delete(@PathVariable Long id) { ... }
}

5. spring-boot-webapp 演示

完整示例在 spring-boot-webapp，包括：

  • 完整 RESTful 风格的用户 API
  • 统一响应格式 ApiResponse
  • 分页、参数校验、异常处理

运行：

cd spring-boot-webapp
mvn spring-boot:run
# 访问 http://localhost:8080/api/users
练习 1： 设计一个"文章管理"API：列表、详情、创建、更新、删除

练习 2： 把你的设计写成表格（URL、HTTP 方法、状态码、请求体、响应体）

练习 3： 启动 spring-boot-webapp，用 Postman 测一遍所有 API
  1. 为什么 URL 用名词不用动词？举一个反例说明动词 URL 的坏处
  2. PUT 和 PATCH 都"更新"，什么时候用哪个？
  3. 如果一个资源"删除"和"禁用"两种操作，REST 风格怎么设计？
